A status page is not a log dump. It should answer three questions instantly: what is affected, is it ongoing, and what should users do.

## Best practices

- Show component-level state instead of a single green/red indicator
- Publish short incident updates with timestamps
- Use maintenance windows to separate planned work from outages
- Keep language direct and status semantics consistent

## Maintenance mode

Maintenance mode allows you to communicate planned work without triggering incidents or alert noise. Show expected duration and affected components.

## Communication during outages

Publish status updates even when there is no new failure cause. Users trust visible, incremental updates more than silence followed by a recovery message.
